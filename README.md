# 6x6 战棋 · 双人联机版

每人一台电脑，通过 4 位房间码配对。手牌和地雷位置由服务器保管，对手**从技术上无法窥探**。

## 本地运行

```bash
npm install
npm start
```

浏览器打开 http://localhost:3000 ，一人点「创建房间」，把房间码发给对方，对方输入后加入。

同一台机器测试：开两个浏览器窗口（其中一个用无痕模式）。

## 为什么需要服务器

如果游戏逻辑跑在浏览器里，完整状态必然存在于两个客户端中，对手按 F12 就能读出你的手牌和地雷坐标。
本项目采用**权威服务器**架构：

- `server.js` 持有唯一的真实状态，所有行动都在服务器端校验（回合归属、手牌是否真有那张牌、坐标是否合法）
- 每个玩家收到的是 `viewFor()` 删减后的视图：
  - 对手手牌 → 只有数量，没有内容
  - 对手地雷 → 完全不下发
  - 抽到什么牌 → 只发给抽牌本人
- 客户端伪造任何消息都会被服务器拒绝，最多只能触发一条报错提示

棋盘上的单位（种类、血量、护盾、攻击力）是公开信息，照常下发，所以高亮范围仍在客户端计算，操作没有延迟感。

## 部署上线

需要支持 **WebSocket 长连接**的平台。Firebase Hosting 只托管静态文件，**不能**单独跑这个服务器。

### 谷歌系：Cloud Run

```bash
gcloud run deploy hex6 --source . --allow-unauthenticated --region asia-east1
```

Cloud Run 支持 WebSocket，会自动读取 `PORT` 环境变量（代码里已适配）。有免费额度，闲置时缩容到零。

如果你已经在用 Firebase Hosting，可以把 Hosting 的 rewrite 指向这个 Cloud Run 服务，就能用同一个 `.web.app` 域名。

### 更简单的替代

- **Render / Railway / Fly.io**：连接 GitHub 仓库，自动识别 `npm start`，免费档即可
- 部署后把网址发给朋友，双方各自打开，用房间码配对

## 已知限制（想继续做可以从这里下手）

- 状态存在内存里，服务器重启后房间丢失 → 可改用 Redis 或 Firestore 持久化
- 断线无法重连回原房间 → 可给每个玩家发一个 token，重连时凭 token 恢复座位
- 没有观战、没有排行榜、没有匹配队列
- `wss://` 由平台自动提供，本地开发用 `ws://`（客户端已按 `location.protocol` 自动切换）
